## Session 1 — 2026-08-11

### What I asked for / what came back
- One search grammar and one sort behind all five console lists, compiled per table. Came back
  as three files (`query-language.ts`, `specs.ts`, `list.ts`) plus five handlers rewired; the
  five handlers lost their copy-pasted `take: limit + 1` / `slice` / `encodeCursor` dance.
- Asked for `interviews>5` on the users list, from the owner's own example. It is not buildable
  as a filter — Prisma has no count predicate in `where` — so it is a sort and an `ignored`
  term, written up as ADR-N10 rather than approximated.

### Methodology trace
Owner walks the console → `query-language.test.ts` red on the grammar, the whitelist, the
totality of the order and the cursor's order-sensitivity → green → five handlers onto
`list.ts` → repo-wide `npm test` green, typecheck + lint clean.

### Friction
- **Prisma reads a bare `null` in a `where` as "no filter", not as `IS NULL`.** `deleted:false`
  compiled to `{ deleted_at: null }` and returned every row — the exact failure ADR-N08 exists
  to prevent, arriving through the code rather than through a typo. `{ equals: null }`.
- **`Prisma.Decimal` throws on garbage; `Number` returns `NaN`.** Two different failure shapes
  for the same bad value, and the throwing one is a 500 on a string that arrived from a link.
  Both are caught and both land in `ignored`.
- **`>=` has to be matched before `>`.** With the naive alternation, `cost>=1` parses as the
  value `=1`, which is unparseable, which means the term is silently ignored — a filter that
  looks applied and is not. Pinned by a test naming all four operators.
- **The `id` tie-break is not a nicety.** Prisma seeks a cursor to the row's position in the
  given order; ties have no single position, so a `created_at`-only order drops or repeats rows
  between pages. The test asserts every sortable field on every spec ends its order on `id`.
- `password_hash:*` was the first thing tried against the users spec, on purpose, and it is now
  a test rather than an anecdote.

### What I rejected and rewrote by hand
- **A spec generated by reflecting over the Prisma model.** It is shorter, it never goes stale,
  and it answers `password_hash:*` the first time anyone puts it on the query string — plus it
  would let a sort reach any column, indexed or not. The whitelist is the security boundary;
  every line in `specs.ts` is a decision. Rewritten as five explicit tables, with a test that no
  term reaches a column the spec did not name.
- **`422 VALIDATION_ERROR` on an unparseable term.** It makes one bad value a failed page and
  says nothing about which of five terms was wrong. `ignored`, echoed (ADR-N08).
- **Keeping `base64url(id)` as the cursor.** It is correct for exactly one order and this task
  made the order a parameter. A `created`-desc cursor spent on a `cost`-asc query returns real
  rows from the middle of a list nobody asked for, with no error — the worst answer available.
  Rewritten as `base64url(sort:dir:id)`, refused on mismatch (ADR-N09).
- **`interviews>5` implemented as a raw `GROUP BY … HAVING` feeding `id: { in: [...] }`.** An
  unbounded id list against a table that only grows, hidden behind an endpoint shape that gives
  no hint of the second query. Cut to sort-only (ADR-N10); the term is reported, not faked.
- **The compiled query replacing each endpoint's dropdown filters** rather than ANDing with
  them. A dropdown and a compiled term are two halves of one question, and honouring one drops
  the other while still looking filtered.
- **A regex with a lookbehind for the tokenizer.** An unclosed quote is the normal state of a
  query being assembled, not an error; a hand-written scan degrades it into "the rest of the
  line" and a regex fought that. 25 lines, and one test that says so.

### Iteration 2 — the owner rejected the interface, not the grammar
The first version shipped this grammar as the thing an operator *types*: the console got a
search box and a syntax panel. The owner's verdict was that a console you have to learn is a
console one person uses. That is a frontend rejection (W13's devlog carries it), but two of its
consequences are backend, and both are in the branch rather than in the superseded `cc38127`:

- **`query.fields` went from `string[]` to `FieldDescriptor[]`.** A list of names is enough to
  *document* a grammar and not enough to *build a control over* one. `{ name, kind, values? }`
  is what lets the console render a date input for a date and a nine-option select for `state`,
  which is the difference between a dropdown that cannot produce an ignored term and one that
  can. The alternative was the client keeping its own table of kinds — a copy of the whitelist,
  which is the thing this envelope exists to avoid.
- **`sessions.active` stopped being a query parameter and became a field.** It was `?active=`
  and a checkbox in the old filter bar, and it survived the first version because no `FieldSpec`
  could express it: two columns and the server's clock, not a leaf on one path. Under a builder
  that offers every field, one field reachable only through a control somewhere else is the
  field an operator stops believing the rest of the list about. Hence ADR-N11: `FieldKind` gains
  `computed`, `FieldSpec` gains `build(value, now)`, and `compileQuery`/`listParams` thread the
  caller's clock so the acceptance ring's fixed clock is honoured.

**What I rejected here too:**
- **`active` as `expires>now`, resolved client-side.** It loses the `revoked_at` half outright,
  and it makes the answer depend on the browser's clock — a laptop an hour fast would show
  revoked sessions as live. `active` was already computed server-side in the row projection for
  exactly that reason; the filter had to agree with the column beside it.
- **`build` as a general escape hatch, with the spec free to return arbitrary SQL.** It takes a
  value and a clock and returns a Prisma condition, nothing else — one field uses it, and the
  test asserts it ANDs with an ordinary field rather than replacing the query. A second instance
  would be eight more lines; a third would be the signal that the schema is missing a column.
- **Defaulting `now` inside `leafFor`.** `compileQuery(input, spec, now = new Date())` takes it
  once, at the top, and `listParams` passes the handler's `clock.now()` down. A default buried
  per-leaf is a clock that is impossible to move in a test and impossible to notice you cannot.
