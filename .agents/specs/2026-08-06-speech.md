## Scope

ElevenLabs is a **voice-generation and transcription vendor**, not a conversation agent. Two
server-side HTTP calls, no agent, no tools, no webhooks, no tunnel, no browser↔provider link.

Owns: the `SpeechProvider` seam, the TTS question-audio route, the STT answer route, per-call
usage accounting, the room turn loop, and the downgrade path that survives from the voice spec.

Does not own: the K2 state machine (I07), the guarded advance (I06), the budget transaction
(I08), prompt building (`ai`), the room shell (`frontend`), or the schema (F02).

## Contracts

### The `SpeechProvider` interface (K3)

```ts
export interface SpeechProvider {
  speak(text: string, opts: { voiceId: string; language: string }):
    Promise<{ audio: Buffer; mime: string; characters: number }>;
  transcribe(audio: Buffer, opts: { mime: string; language: string }):
    Promise<{ transcript: string; seconds: number }>;
}
```

One real driver (`ElevenLabsSpeech`), one fake (`FakeSpeechProvider`, `failNext`), swapped
wholesale by `setSpeechProvider` — the `storage.ts` / `voiceSeam` pattern already in the repo.
The acceptance ring drives the fake; no network.

`voiceId` comes from `personas.voice_id` (F02, seeded). Not env.

### Question audio (TTS)

`GET /interviews/:id/questions/:index/speech` · `requireAuth` · owner only.

- 200 `audio/mpeg`, bytes only. No JSON envelope, no key, no provider URL.
- Cached in object storage under `speech/{questionId}.mp3` via `src/lib/storage.ts` (`put`/`get`,
  already shipped by I11/I12). A cache hit makes **no** provider call.
- Refused before any provider call when: not the owner (`FORBIDDEN`), the index is not the
  current question (`QUESTION_NOT_CURRENT`), the interview is not in a voice-capable state
  (`INVALID_STATE_TRANSITION`), the ceiling has passed (`VOICE_SESSION_EXPIRED` + the interview
  ends `time_exhausted`), the provider is unconfigured or failing (`VOICE_UNAVAILABLE`).

### Answer audio (STT)

`POST /interviews/:id/answers/audio` · `requireAuth` · `requirePublicOrigin` · owner only ·
`multipart/form-data`, one `audio` part.

- multer memory storage, limits copied from `modules/interview/uploads.ts` (`files: 1`,
  `fields: 1`, `parts: 3`, `fileSize` from config).
- `transcribe()` → the transcript is parsed by the **existing** `answerInputSchema`
  (`inputMode: 'voice'`) and handed to `advanceWithAnswer`. No second answer path.
- 200 with the same `{ state, nextIndex }` body `POST /answers` returns.
- Errors: `UPLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`, `SPEECH_AUDIO_INVALID` (undecodable or
  empty), `SPEECH_TRANSCRIPTION_FAILED` (provider refused), plus the state guards above. None
  mutates the interview.

### Cost (§7.3, K13)

Every provider call writes one `llm_calls` row and charges `spent_usd` in **one** transaction,
through the existing `recordLlmCall` helper (`src/lib/db.ts`) inside `withBudget` (I08):

| Call | `provider` | `model` | `unit_kind` | `units` |
|---|---|---|---|---|
| TTS | `elevenlabs` | `tts` | `character` | characters spoken |
| STT | `elevenlabs` | `stt` | `second` | audio seconds |

`UnitKind` already has `character` and `second` (F02) — no enum migration. `model-prices.yaml`
replaces its single `elevenlabs/conversational` row with these two.

No reconciliation, no idempotency key: a call that returns bytes is billed once, at the call
site, in the request that made it. There is no redelivery to defend against.

### The turn loop (§3.2)

```
GET …/speech  →  play audio          (beat: speaking)
              →  record with VAD     (beat: listening)   ← stops on ~2 s silence, manual stop always available
              →  POST …/answers/audio (beat: acknowledging)
              →  refetch GET /state  →  next question
```

Discrete turns. No streaming, no partial transcripts, no barge-in. Truth is still
`GET /interviews/:id/state`; the loop never advances the index client-side.

### Ceiling (§7.3)

`VOICE_MAX_ROUND_SECONDS` (720) / `VOICE_MAX_INTERVIEW_SECONDS` (1500), measured from
`interviews.started_at`. Re-checked server-side on **every** TTS and STT call — the client's VAD
is a convenience, never the enforcement. Past the ceiling: `applyTransition(evaluating,
{ endedReason: 'time_exhausted' })`, the same edge the retired webhook gate used.

### Downgrade (§3.2, §3.8)

Unchanged from the voice spec and unchanged in code: `voice → text` only, same `interviewId`,
same index, through `downgradeToText` and `POST /interviews/:id/voice/downgrade`. Every fatal
speech failure and a denied microphone route here.

## Behaviour

- Voice is the **default** mode at setup; text is chosen, not fallen into.
- Duration is user-selectable at setup, capped by the configured ceiling.
- `GET /state` gains `startedAt` and `expiresAt` so the room can render time remaining.
- Personas: the round's persona supplies both the voice and the tile that shows as active. One
  active speaker, decided by `state`, never by audio (K2).

## Failure modes

| Situation | Code | Effect |
|---|---|---|
| Provider unconfigured / 5xx / timeout ×3 | `VOICE_UNAVAILABLE` 503 | downgrade to text, interview continues |
| Audio undecodable or empty | `SPEECH_AUDIO_INVALID` 400 | no state change; the room re-records |
| Transcription returns nothing usable | `SPEECH_TRANSCRIPTION_FAILED` 502 | no state change; retry or type the answer |
| Ceiling passed | `VOICE_SESSION_EXPIRED` 403 | interview ends `time_exhausted` |
| Mic denied at pre-join | — | downgrade to text before any provider call |

Every one of these is distinguishable in the room. "The voice connection dropped" is retired
with the connection that could drop.

## Observability

`SPEECH_TTS_SERVED` (cached | minted), `SPEECH_STT_TRANSCRIBED`, `SPEECH_PROVIDER_FAILED`,
`VOICE_DOWNGRADED_TO_TEXT`, `VOICE_TIME_EXHAUSTED` — all with `interviewId` and `traceId`.

## Security

- **The API key never reaches the browser.** Both calls are server-side; the browser talks only
  to our origin. CSP stays `connect-src 'self'` — the voice spec's one CSP relaxation is retired,
  not configured.
- **Candidate audio is transient.** Buffered in memory, sent to the provider, discarded. Never
  written to object storage, never to the DB. Only the transcript persists — the same artifact
  text mode produces.
- **The consent copy must change.** Pre-join today says nothing is recorded. Under this
  architecture the answer audio *leaves the browser* for transcription. The copy must say so.
  Silence here would be the one lie a user would act on. Ties into issue #61 (no KVKK/GDPR
  surface).
- No key, no audio bytes, no transcript text in any log line (K6, §7.2).

## Open questions

1. **Scribe language handling.** Whether `language_code` is passed explicitly from
   `interviews.language` or left to auto-detect. **Decides:** `speech`, by a spike against the
   API. **Blocks:** nothing structural — it is one request field. **Recommended default:** pass
   it explicitly; auto-detect on a Turkish answer to an English question is exactly the failure
   I10/#149 already document elsewhere.
2. **VAD threshold and silence window.** The RMS threshold and the ~2 s window are guesses until
   heard. **Decides:** `speech`, at S06, by trying it. **Blocks:** nothing — the manual stop
   makes any threshold survivable. **Recommended default:** 2 s, tunable by config, manual stop
   always visible.
3. **TTS cache eviction.** Cached question audio is never deleted. **Decides:** `infra`.
   **Blocks:** nothing near-term — an interview's questions are a few kB of MP3. **Recommended
   default:** leave it; revisit with the soft-delete/retention work.

## Acceptance criteria

1. `GET /interviews/:id/questions/:index/speech` by the owner returns `audio/mpeg` for the
   current question; a non-owner returns `FORBIDDEN`; the response body and headers carry no
   API key.
2. The same question requested twice makes exactly **one** provider call — the second is served
   from object storage.
3. `POST /interviews/:id/answers/audio` by the owner persists an `answers` row with
   `input_mode = 'voice'` through the I06 guarded advance and advances `current_index`.
4. An oversize part returns `UPLOAD_TOO_LARGE`, a non-audio mime `UNSUPPORTED_MEDIA_TYPE`, and
   an undecodable payload `SPEECH_AUDIO_INVALID` — none of them changes any interview row.
5. A TTS call writes one `llm_calls` row (`provider='elevenlabs'`, `model='tts'`,
   `unit_kind='character'`) and an STT call one (`model='stt'`, `unit_kind='second'`), each
   incrementing `spent_usd` in the same transaction as its insert.
6. A TTS or STT call attempted past the round or interview ceiling makes **no** provider call,
   returns `VOICE_SESSION_EXPIRED`, and leaves the interview `ended_reason = 'time_exhausted'`.
7. A fatal provider failure downgrades the same interview to text: same `interviewId`, same
   index, earlier answers keep `input_mode='voice'`, later ones are `'text'`, and `mode` never
   returns to `voice`.
8. No log line, error body or test fixture contains the API key, audio bytes, or transcript
   text.
9. The built room opens **no** cross-origin connection: the CSP at `frontend/src/middleware.ts`
   still reads `connect-src 'self'`, and no `WebSocket` is constructed anywhere in
   `frontend/src`.
10. Denying the microphone at pre-join downgrades the interview to text with no provider call;
    resuming a voice interview from the history list routes through pre-join, not straight into
    the room.
11. `/interviews/new` defaults to voice, and the chosen duration is honoured up to the
    configured ceiling and refused above it.
12. `GET /interviews/:id/state` returns `startedAt` and `expiresAt`, and the room renders time
    remaining from them.
13. Each failure in `## Failure modes` renders its own copy in the room, in both locales, with
    an action that can succeed. No failure renders "the voice connection dropped".
14. Candidate audio is never persisted: after a completed voice interview, no object-storage key
    and no DB column holds audio for it.
