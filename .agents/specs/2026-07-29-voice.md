# voice — spec

**Date:** 2026-07-29
**Status:** draft
**Derives from:** IDEA.md K3, §3.2, §3.5, §3.6 (drivers), and the mechanics it plugs into:
§7.3 (voice cost path), §7.4 (CSP exception), §5.5/§5.3 (`voice_fallback.feature` + the
`VoiceSession` test seam), §3.8 (the text room it downgrades **to**), §12/§15.1 (second
scope band, authored last). **Overlaps** `backend` (routes `/webhooks/*`, owns the room
state machine K2) and `frontend` (owns the room shell this dresses with voice controls).
**Supersedes:** the "recording" in `USER_STORIES.md` per §3.2 (no audio/video is recorded).

## Scope

This spec pins the **voice layer** — the one deliberate exception to the single-origin rule
(K14). It owns the `VoiceSession` interface and its fake, the browser↔ElevenLabs direct
connection, the session-token mint, the server-to-server webhook contract, the time-based
cost ceiling and its post-call reconciliation, the two avatar drivers, and the mandatory
**voice→text downgrade**. It is the *last* area authored; nothing in the MVP text path
depends on it (§12).

It owns:

- **The `VoiceSession` interface (K3).** The seam ElevenLabs sits behind and `FakeVoiceSession`
  substitutes for, so `voice_fallback.feature` runs with no network (§5.5).
- **Session mint (§3.5).** The backend endpoint that mints a short-lived ElevenLabs signed
  session token, writes the `voice_sessions` row (`interviewId`, `nonce`, `expires_at`), and
  binds the time ceilings into the token — the browser gets a token, **never** the API key.
- **The webhook contract (§3.5).** `submit_answer` / `next_question` / `end_round` as
  server-to-server calls from ElevenLabs to `/webhooks/elevenlabs/*`: HMAC-SHA256 + timestamp
  window, `(interviewId, nonce)` authorisation against an unexpired `voice_sessions` row,
  legal-K2-transition check, expiry re-check, and payload/response shapes.
- **Cost ceiling & reconciliation (§7.3, §3.5).** 12 min/round + 25 min/interview minted into
  the token, enforced client-side **and** re-checked on every webhook; the post-call webhook
  that has `worker` write an `llm_calls` row (`provider='elevenlabs'`, `unit_kind='second'`)
  and reconcile `spent_usd`; `ended_reason = 'time_exhausted'`.
- **Avatar drivers (§3.6).** `AmplitudeAvatarDriver` (voice, `AnalyserNode` on TTS) and
  `EventAvatarDriver` (voice-fallback + text, SSE-driven) behind the shared driver interface.
- **The voice room surface (§3.2).** Live ASR transcript, mic-level bar, optional self-camera
  tile (off by default, never uploaded, never recorded), the active-speaker signal for the two
  persona tiles, the pre-join device check that runs **before** a session is minted, and the voice
  controls — dressed on
  the room shell `frontend` owns.
- **The downgrade rule (§3.2, §3.8).** Any voice failure continues the *same* interview in
  text; `interviews.mode` goes `voice → text`, **never** the reverse.

**Not in this spec** (named owner):

- The K2 **state machine** itself (which transition is legal), the room-state shape, the SSE
  nudge stream, and the `/webhooks/*` **router mount** — `backend` (K2, §3.8). This spec says
  what a webhook *requests*; `backend` owns whether the transition is legal and rejects it with
  `INVALID_STATE_TRANSITION`.
- The `voice_sessions`, `answers` (`input_mode`), `llm_calls` **tables/enums** and the
  soft-delete/spent_usd rules — `db` (K13). This spec writes rows through them; `db` owns their
  shape (`voice_sessions(interview_id, nonce, expires_at, consumed_at)`, `InputMode`,
  `EndedReason.time_exhausted`).
- The room **shell**, route, React Query data layer, i18n, `EventAvatarDriver` **wiring in text
  mode** — `frontend` (K11, §3.8). This spec adds the voice-only controls and the amplitude
  driver; `frontend` owns the shell and the text-mode event driver.
- The **CSP edge mechanics, the `tunnel` service, `.env`/key delivery** — `infra` (K14, §7.4,
  §9.3). This spec *supplies* the ElevenLabs WSS origin the CSP must allow and *requires* the
  tunnel; `infra` makes them serve.
- The `AvatarState` enum members, avatar **assets** and budgets — `ui` (§3.6, §4.x). This spec
  drives which state shows; `ui` fixes the enum and the images.
- Prompt building, occupation/language logic, price tables — `ai` (K9, K15). The voice agent is
  "a mouth and an ear"; interview logic stays server-side (§3.5).

## Contracts

### The `VoiceSession` interface (K3)

The seam. The real implementation wraps ElevenLabs; `FakeVoiceSession` is the test double that
`voice_fallback.feature` drives (§5.5). Both expose the same surface so the state machine and
the fallback path are provider-agnostic:

```ts
interface VoiceSession {
  mint(interviewId: string): Promise<{
    token: string            // short-lived ElevenLabs signed session token — never the API key
    wssOrigin: string        // the origin the CSP connect-src must allow (§7.4)
    dynamicVars: { interviewId: string; nonce: string }  // echoed back by every webhook
    expiresAt: string        // min(roundCeiling, interviewCeiling) from now (§7.3)
  }>
  // FakeVoiceSession.failNext() forces the next mint/turn to error → exercises downgrade
}
```

### Session mint

| Method + path | Effect | Success | Error codes |
|---|---|---|---|
| `POST /interviews/:id/voice/session` | Owner-checked. Mints an ElevenLabs signed session token, inserts a `voice_sessions` row (`nonce` = unguessable secret, `expires_at` = the tighter of the round/interview ceiling), returns token + `wssOrigin` + `dynamicVars` | `201`, mint payload above | `INTERVIEW_NOT_FOUND`, `FORBIDDEN`, `UNAUTHENTICATED`, `VOICE_UNAVAILABLE`, `INVALID_STATE_TRANSITION` |

- Mint is refused unless the interview is in a state that can host a voice round (K2, `backend`);
  a mint in the wrong state is `INVALID_STATE_TRANSITION`, not a silent no-op.
- `VOICE_UNAVAILABLE` (mint fails / provider down) is the client's cue to **downgrade to text**
  (below), not an error the user sees as a dead end.
- The browser opens the WSS to ElevenLabs with the returned token. **The API key never reaches
  the client** (§3.5); a mint payload carrying it is a defect.

### Webhook contract (§3.5)

Server-to-server, ElevenLabs → `/webhooks/elevenlabs/:action`, `action ∈ { submit_answer,
next_question, end_round }`. They carry **no** browser cookie, so identity/authn/authz are
carried by the payload and the signature:

```jsonc
// headers
"X-ElevenLabs-Signature": "sha256=…",   // HMAC-SHA256 over the raw body, key = ELEVENLABS_WEBHOOK_SECRET
"X-ElevenLabs-Timestamp": "…"           // rejected outside the window (replay guard)
// body
{ "interviewId": "…", "nonce": "…", "transcript": "…", /* action-specific */ }
```

Every webhook passes **four gates, in order** — a failure at any gate rejects the call and
mutates nothing:

1. **Signature.** HMAC-SHA256 over the raw body against `ELEVENLABS_WEBHOOK_SECRET`; mismatch →
   `WEBHOOK_SIGNATURE_INVALID` (`401`).
2. **Freshness.** Timestamp within the window; outside → `WEBHOOK_REPLAY_REJECTED` (`401`).
3. **Authorisation.** `(interviewId, nonce)` matches an **unexpired, unconsumed**
   `voice_sessions` row; no match or `expires_at` passed → `VOICE_SESSION_INVALID` (`403`).
4. **Legality + expiry.** The requested transition is legal from the current K2 state
   (`backend`), and the wall-clock ceiling has not passed. `end_round` is accepted **only** when
   the round's questions are exhausted or an explicit shortening decision exists (§3.5).
   Illegal → `INVALID_STATE_TRANSITION` (`409`, owned by `backend`/`db`); ceiling passed →
   `VOICE_SESSION_EXPIRED` (`403`) and the interview ends `time_exhausted`.

| Action | Effect on pass | Answer row |
|---|---|---|
| `submit_answer` | Persist the candidate turn; advance the K2 clock | `answers` row, `input_mode = 'voice'` (`db`) |
| `next_question` | Deliver the next question (K2 `current_index++`) | — |
| `end_round` | Close the round when exhausted / shortened | — |

### Cost ceiling & reconciliation (§7.3)

- **Minted ceiling:** `VOICE_MAX_ROUND_SECONDS` (720 / 12 min) and `VOICE_MAX_INTERVIEW_SECONDS`
  (1500 / 25 min) are baked into `expires_at`; the client terminates at expiry **and** every
  webhook re-checks it (gate 4). This is a time ceiling, **partly retrospective** — unlike the
  text path's pre-call `budget_usd` check (§7.3, owned by `ai`).
- **Post-call reconciliation:** ElevenLabs' post-call webhook delivers duration/usage; `worker`
  writes an `llm_calls` row (`provider='elevenlabs'`, `unit_kind='second'`, `units` = seconds)
  and reconciles `interviews.spent_usd` in the single K13 transaction (`db`). This spec defines
  the webhook payload → row mapping; `worker` runs it (`backend` §-scope note: worker owns voice
  reconciliation).
- Hitting either ceiling sets `ended_reason = 'time_exhausted'` (`db` enum); the report is then
  generated from whatever answers exist — the user loses nothing (§7.3).
- The global `AI_ENABLED=false` kill switch and the per-user daily cap (5/day) apply to voice
  too (§7.3, values owned by `backend`/`infra`); mint is refused with `VOICE_UNAVAILABLE` when
  the kill switch is off.

### Avatar drivers (§3.6)

Both implement the shared driver interface `ui`/`frontend` consume; the `AvatarState` enum is
`ui`'s. Which driver runs is a function of mode and SDK capability — **not** of the avatar
assets, which are identical either way:

| Driver | Mode | Signal | Status |
|---|---|---|---|
| `AmplitudeAvatarDriver` | voice | `AnalyserNode` on the agent's TTS output | **gated** on §15.1.3 — see Open questions |
| `EventAvatarDriver` | voice-fallback + text | SSE `speaking.start`/`speaking.end`/`thinking.start`, timer-interpolated | always available (`frontend` owns the text wiring) |

If the ElevenLabs web SDK does not expose a `MediaStream`/`AudioNode` for agent output, the
amplitude driver is **dropped** and the event driver serves both modes (§3.6). The avatar and
its visual score do not depend on the answer.

### Voice room surface (§3.2)

Added onto the room shell `frontend` owns:

- **Live ASR transcript** panel (`aria-live`, per `ui` §4.4, collapsible per `frontend`),
  **mic-level bar**, **voice controls** (mute, camera, captions, finish-answer, leave) collected
  into the bottom bar `frontend` composes.
- **Self-camera tile** — **optional, user-togglable, off by default**. The `getUserMedia`
  stream binds **only** to a local `<video>`; **no WebRTC peer, no upload, no recording** (§3.2).
  The sole stored artifact is the transcript.
- **Active-speaker signalling on the two persona tiles** (§3.2). The tiles themselves are
  `frontend`'s; voice supplies the *signal* that drives the ring and the waveform — the same
  amplitude source the `AmplitudeAvatarDriver` uses when it exists, and the event stream otherwise.
  Only the round's persona is ever active: rounds are sequential and exactly one question is live
  (K2), so there is no cross-talk to arbitrate and voice never animates two tiles at once.
- **`● LIVE` only — no `REC` indicator, and no consent screen.** Nothing is recorded (§3.2), and a
  recording badge on a product that records nothing is a claim a user would act on. Voice adds no
  recording affordance, in any mode, ever.
- **Pre-join is a separate route** (`/interviews/:id/pre-join`, `frontend` screen 10) rather than a
  panel inside the room: the device check and the permission prompt must happen **before** the WSS
  session is minted, so a denied microphone downgrades to text without ever having spent a session
  token. Voice owns what the check tests (mic level, camera preview, permission state) and the
  "nothing is recorded" note; `frontend` owns the screen it sits on.
- The client connects **directly** to the ElevenLabs WSS using the minted token; this is the
  single CSP `connect-src` exception (§7.4) — the exact origin is `wssOrigin` from the mint,
  supplied to `infra` (Open questions).

### Downgrade (§3.2, §3.8)

`interviews.mode` is `voice → text` **only, never the reverse** (§3.8). Any of: no mic,
permission denied, mint `VOICE_UNAVAILABLE`, WSS drop, or a `VoiceSession` fatal error →
the **same** interview continues in text (§3.8), same `interviewId`, same question index, same
`answers` table (now `input_mode='text'`). This is the mandatory-requirement guarantee: the
case never depends on the voice layer (§3.2).

## Behaviour

1. **The API key never reaches the browser.** The client holds only a short-lived signed
   session token from the mint; a build or payload exposing `ELEVENLABS_API_KEY` client-side is
   a defect (§3.5).
2. **Every webhook passes all four gates before mutating anything** — signature, freshness,
   `(interviewId, nonce)` authorisation, legality+expiry — in that order; a failure at any gate
   changes no state (§3.5). Voice tool-calls hold no authority a schema/state check doesn't grant
   (§7.1 item 4).
3. **The time ceiling is enforced twice** — client terminates at `expires_at`, and every webhook
   re-checks it; a webhook arriving after expiry is rejected `VOICE_SESSION_EXPIRED` and the
   interview ends `time_exhausted` (§7.3).
4. **Any voice failure downgrades to text; nothing upgrades.** The interview continues in the
   same room, same index; `mode` never returns to `voice` mid-interview (§3.2, §3.8).
5. **No audio or video is ever recorded or uploaded.** Camera is off by default and local-only;
   the transcript is the only artifact (§3.2) — this supersedes `USER_STORIES.md`.
6. **The driver choice is invisible to the interview.** Text mode and voice-fallback both use
   `EventAvatarDriver`; voice with a working audio node may use `AmplitudeAvatarDriver`. The
   `AvatarState` sequence a candidate sees does not reveal which (§3.6).
7. **`FakeVoiceSession` makes the fallback testable.** `voice_fallback.feature` drives it to
   fail on command and asserts the interview downgrades to text and survives — no ElevenLabs
   network in CI (§5.5, K3).
8. **Local voice needs the tunnel.** ElevenLabs cannot reach `http://localhost`; without the
   `dev`-profile `cloudflared` tunnel wired into `PUBLIC_ORIGIN`, voice mode does not work
   locally (§3.5, `infra`). Text mode is unaffected.

## Failure modes

Voice failures split into **webhook rejections** (an HTTP boundary crossed by ElevenLabs) and
**client-side degradations** (which downgrade, not error). Codes join the shared registry (`F01`).

| Condition | Code | HTTP | Recovery |
|---|---|---|---|
| Webhook HMAC signature mismatch | `WEBHOOK_SIGNATURE_INVALID` | 401 | Reject; nothing mutates (§3.5) |
| Webhook timestamp outside the window (replay) | `WEBHOOK_REPLAY_REJECTED` | 401 | Reject; replays cannot re-drive the machine (§3.5) |
| `(interviewId, nonce)` no match / consumed | `VOICE_SESSION_INVALID` | 403 | Reject; only a live minted session drives transitions (§3.5) |
| Wall-clock ceiling passed | `VOICE_SESSION_EXPIRED` | 403 | Interview ends `time_exhausted`; report from existing answers (§7.3) |
| Requested transition illegal from current state | `INVALID_STATE_TRANSITION` (`backend`/`db`) | 409 | Reject; K2 is the authority (§3.5 item 4) |
| Mint fails / provider down / kill switch off | `VOICE_UNAVAILABLE` | 503 | Client **downgrades to text** — not a dead end (§3.2) |
| Mic denied / WSS drop / `VoiceSession` fatal error | *(not an error)* — downgrade signal | — | Same interview continues in text; `mode='text'` (§3.2, §3.8) |
| Camera denied | *(not an error)* | — | Camera stays off (optional, off by default); interview proceeds (§3.2) |

## Observability

Every voice event logs through the K6 contract — `logger.<level>({ traceId, interviewId,
nonce: '[redacted]' }, "EVENT_NAME")` — and the **`nonce`, the session token and the API key are
never logged** (they are session secrets, §7.2/K6). Mandatory events: `VOICE_SESSION_MINTED`,
`VOICE_WEBHOOK_RECEIVED` (with `action`), each rejection code above, `VOICE_DOWNGRADED_TO_TEXT`
(the single most operationally important line — it explains why a "voice" interview has text
answers), `VOICE_USAGE_RECONCILED` (seconds + reconciled `spent_usd`), and `VOICE_TIME_EXHAUSTED`.
The webhook rejections are the security-relevant signal an admin searches by `interviewId`
(§3.5); no transcript text or persona prompt appears in a log line.

## Security

Voice is the project's widest trust boundary — a browser talking to a third party and that third
party calling us back:

- **Direct browser↔ElevenLabs is the *only* single-origin exception (K14, §3.5).** It costs one
  CSP `connect-src` entry (the WSS origin) and nothing more; `default-src 'self'` holds for
  everything else (§7.4). No other cross-origin relaxation is introduced.
- **The API key stays server-side.** The browser gets a short-lived signed token; the key lives
  in `.env` only (§9.3, `infra`) and is never minted into a client payload (§3.5).
- **Webhooks are authenticated data, not trusted callers.** HMAC + timestamp window + nonce
  match + legal-transition + expiry (all four gates) mean a forged or replayed webhook cannot
  advance an interview — the job listing reaching an LLM with tool-call authority is defanged by
  the schema+state authority check, not by trusting the caller (§7.1 item 4, §3.5).
- **`voice_sessions.nonce` is an unguessable secret** paired with `interviewId`; it is never
  logged, never returned to a non-owner, and expires (`db` §, §3.5).
- **No media is recorded.** Camera is local-only and off by default; no audio/video leaves the
  browser, so there is no recording to leak (§3.2).

## Open questions

Each names who decides and what it blocks. Must be empty before `approved`.

1. **ElevenLabs agent provisioning — console vs API (§15.1.2).** Are the two agents
   (`ELEVENLABS_AGENT_ID_HR`, `_TECH`) created by hand in the ElevenLabs console and pasted into
   `.env`, or provisioned via API at startup/seed? **Decides:** `voice` (owns the provider
   contract) + `infra` (owns `.env`/seed wiring — its Open question 2). **Blocks:** the final
   Voice `.env` key list and whether a seed step provisions agents — nothing in the text MVP.
   **Recommended default:** console-created, pasted into `.env` as two ids; provisioning-by-API
   deferred until it earns its complexity (YAGNI).
2. **ElevenLabs web SDK audio surface → `AmplitudeAvatarDriver` existence (§15.1.3, §3.6).** Does
   the SDK expose a `MediaStream`/`AudioNode` for the agent's TTS output? **Decides:** `voice`,
   by a spike against the SDK **before** the driver is built. **Blocks:** only whether the
   amplitude driver ships — the event driver serves both modes if it does not, so the room, the
   avatar and its score are unaffected (§3.6). **Recommended default:** assume **no**; ship the
   event driver for both modes, add the amplitude driver only if the spike confirms the node.
3. **The exact ElevenLabs WSS origin for the CSP `connect-src` (§7.4).** The edge must allow one
   extra origin for the direct connection; the concrete value is what the SDK actually dials.
   **Decides:** `voice` supplies the value; `infra` parameterises the CSP to accept it (its Open
   question 3/4). **Blocks:** the voice room's live connection only — the text-mode CSP stays
   `default-src 'self'`. **Recommended default:** read the origin from the mint's `wssOrigin` and
   pin it in `.env` so the CSP is configured, never hard-coded in two places.
4. **Session-token TTL vs the 12/25-minute ceilings (§3.5, §7.3).** The ElevenLabs signed
   session token has its own provider TTL; whether it can be minted to exactly `min(roundLeft,
   interviewLeft)` or must be refreshed mid-round is unverified against the SDK. **Decides:**
   `voice`, in the same SDK spike as (2). **Blocks:** whether a long round needs a token refresh
   round-trip — not the ceiling itself, which is always re-checked server-side per webhook.
   **Recommended default:** mint to the tighter ceiling and rely on the server-side webhook
   re-check as the true enforcement; add refresh only if the provider TTL is shorter than a round.

## Acceptance criteria

Each observable from outside — the HTTP webhook surface, the mint endpoint, or the
`voice_fallback.feature` acceptance ring (§5.3, driven against `FakeVoiceSession`).

1. `POST /interviews/:id/voice/session` by the owner returns a token, `wssOrigin`, and
   `{ interviewId, nonce }`, and writes a `voice_sessions` row with `expires_at` = the tighter
   of the round/interview ceiling; the payload contains **no** API key (§3.5).
2. A non-owner mint returns `FORBIDDEN`; a mint in a state that cannot host voice returns
   `INVALID_STATE_TRANSITION`; a mint with the kill switch off returns `VOICE_UNAVAILABLE` (§3.5,
   §7.3).
3. A webhook with a bad HMAC returns `WEBHOOK_SIGNATURE_INVALID` and changes no state; a stale
   timestamp returns `WEBHOOK_REPLAY_REJECTED` (§3.5).
4. A webhook whose `(interviewId, nonce)` matches no unexpired row returns `VOICE_SESSION_INVALID`;
   one arriving after `expires_at` returns `VOICE_SESSION_EXPIRED` and the interview ends
   `ended_reason = 'time_exhausted'` (§3.5, §7.3).
5. A valid `submit_answer` webhook persists an `answers` row with `input_mode = 'voice'` and
   advances the K2 clock; an `end_round` before the round's questions are exhausted (no shortening
   decision) is rejected `INVALID_STATE_TRANSITION` (§3.5).
6. `voice_fallback.feature`: an interview in voice mode whose `FakeVoiceSession` reports a fatal
   error **downgrades to text** and completes, same `interviewId`, with later answers
   `input_mode='text'`; `mode` never returns to `voice` (§3.2, §3.8, §5.5).
7. The post-call reconciliation webhook makes `worker` write an `llm_calls` row
   (`provider='elevenlabs'`, `unit_kind='second'`, `units` = seconds) and update `spent_usd` in
   one transaction (§3.5, §7.3, `db` K13).
8. The self-camera tile is off by default; enabling it binds `getUserMedia` to a local `<video>`
   only — no network request carries audio or video, and no recording artifact is produced (§3.2).
9. The built voice room opens exactly one cross-origin connection, to the `wssOrigin` allowed by
   the edge CSP; every other request is same-origin (§7.4).
10. `VOICE_DOWNGRADED_TO_TEXT`, the webhook rejection codes, and `VOICE_USAGE_RECONCILED` are
    emitted through the K6 logger with `interviewId`, and no log line contains the nonce, token,
    API key, or transcript text (K6, §7.2).
11. **Pre-join precedes the mint.** A voice interview reaches `/interviews/:id/pre-join` before any
    `POST /interviews/:id/voice/session` is issued; denying the microphone there downgrades the
    interview to text with **no** `voice_sessions` row ever created (§3.2, §3.8).
12. **One active speaker.** While `state = 'hr_round'` the voice layer drives the ring/waveform on
    the HR tile only, and on the tech tile only in `tech_round`; there is no state in which voice
    reports two active speakers (K2).
13. **No recording affordance exists.** The voice room renders no `REC` indicator and no consent
    dialog, and no code path produces an audio or video artifact (§3.2).
