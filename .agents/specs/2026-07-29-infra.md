# infra — spec

**Date:** 2026-07-29
**Status:** draft
**Derives from:** IDEA.md K6, K12, K14, §9.3, §10, §11, and the cross-cutting mechanics
§3.5 (local webhook tunnel), §5.2 (single-file `schema.prisma` + shadow DB), §7.4 (CSP /
edge headers), §8.1 (`/assets` + font origin), §8.3 (bounded external calls it must make
possible, not implement). **Overlaps every area** — it is the ground the others run on.
**Supersedes:** —

## Scope

This spec pins the **runtime platform**: the container inventory and their Compose wiring,
the single published edge, object storage and its two access classes, the environment
schema, the log transport, and the CI/CD pipeline. It owns *how the system boots, is
reached, stores bytes, is configured, and ships* — never *what any request computes*.

It owns:

- **Containers & Compose (§10).** The service inventory (`edge`, `web`, `api`, `worker`,
  `db`, `redis`, `minio`, `migrate`, `tunnel`, and the profile-gated `elasticsearch` /
  `kibana`), their images, build contexts, healthchecks, `depends_on: { condition:
  service_healthy }` ordering, the one-shot migration service, and the Compose **profiles**
  that keep the heavy and optional services out of a default `docker compose up`.
- **Edge (K14).** The single Caddy reverse proxy — the *only* container that publishes a
  host port — its route table (`/` → `web`, `/api/*` → `api`, `/assets/*` → `minio`), and
  the security/response headers (CSP, HSTS-class, cache) it stamps (§7.4, §8.1).
- **Object storage (K12).** The MinIO (S3-API) bucket, the **two access classes**
  (public-read avatars vs private everything-else), and the **signed-URL** mechanism (short
  TTL) that reads private objects — the enforcement of the classification `ui`/`backend`
  declared.
- **Environment (§9.3).** The single Zod-validated env schema, the fail-fast startup check,
  and the committed `.env.example`; the wiring of every provider key and cost-safety flag
  the other areas *consume* (they own the behaviour; infra owns that the value arrives).
- **Logging transport (K6).** That `logger.<level>({…, traceId, interviewId}, "EVENT")`
  writes structured JSON to stdout, how Compose collects it, and the **optional**
  Elasticsearch/Kibana sink behind a profile. The *log-line contract* is honoured by every
  service; infra owns the *transport and sink*, not the call sites.
- **Deploy & CI (§11).** The GitHub Actions pipeline (lint, typecheck, build, migrate-check,
  Cucumber acceptance ring), the migration strategy, and the single-VM deployment shape.

**Not in this spec** (named owner):

- The `schema.prisma` **contents**, every migration's SQL, seed data, and the repo helpers
  — `db` (K13, §5.2). Infra owns the `migrate` service that *runs* `prisma migrate deploy`
  and the shadow-DB init SQL that makes migrations *diff*; it authors no model.
- Any **HTTP handler, state machine, or business rule** — `backend` (K1, K2). Infra routes
  to `/api` and defines `/healthz`/`/readyz` *wiring and dependency gating*; `backend` owns
  the endpoints' bodies and the `NOT_READY` semantics.
- **What the LLM/voice providers are called with**, prompt files, price tables, Zod response
  schemas — `ai` (K9, K15) and `voice` (K3). Infra provisions their keys and ships their
  config files into the image; it never reads a prompt.
- **Design tokens, the CSP's font/asset *intent*, avatar key layout and budgets** — `ui`
  (§4.2, §3.6). Infra *serves* `/assets` public-read with the immutable cache header and
  self-hosts `next/font`; `ui` fixes families, budgets and keys.
- **Route map, SSE, i18n, React Query** — `frontend` (K11). Infra serves `web` behind the
  edge; it composes no screen.

## Contracts

The concrete platform surface other areas bind to.

### Container inventory (§10)

| Service | Image / build | Publishes port | Profile | Healthcheck gates |
|---|---|---|---|---|
| `edge` | Caddy (official) | **yes — the only one** (`:80`, prod `:443`) | default | — |
| `web` | build, context = **repo root**, `frontend/Dockerfile` | no | default | HTTP `GET /` 200 |
| `api` | build, context = **repo root**, `backend/Dockerfile` | no | default | `GET /healthz` 200 |
| `worker` | build, context = **repo root**, `worker/Dockerfile` | no | default | process/liveness |
| `db` | Postgres (official) | no | default | `pg_isready` |
| `redis` | Redis (official) | no | default | `redis-cli ping` |
| `minio` | MinIO (official) | no | default | MinIO `/minio/health/ready` |
| `migrate` | reuses `api` image, one-shot | no | default | runs to completion, exits 0 |
| `tunnel` | cloudflared | no | `dev` (local webhooks) | — |
| `elasticsearch` | ES (official) | no | `observability` | ES `/_cluster/health` |
| `kibana` | Kibana (official) | no | `observability` | Kibana `/api/status` |

- **Build context is the repo root for every built image** (§10.1) — npm workspaces put
  shared packages (`@interviewly/ai`, shared types) above each service dir, so a
  service-scoped context cannot see them. Each `Dockerfile` lives in its service dir but is
  invoked with `context: .` at root.
- **`edge` is the sole port-publisher** (K14). No other service maps a host port in the
  committed `compose.yaml`. The developer-local `compose.override.yaml` **is auto-loaded by
  Compose** and *may* expose `db`/`minio`/etc. for debugging — it is **git-ignored**, ships
  no behaviour, and its absence must never change how the stack runs (§10.2, §11.3).

### Compose profiles (§10.2)

- **default** (no profile): `edge web api worker db redis minio migrate` — a bare
  `docker compose up` yields a working, seeded, single-origin app.
- **`dev`**: adds `tunnel` for ElevenLabs/webhook callbacks into localhost (§3.5).
- **`observability`**: adds `elasticsearch` + `kibana`. ES pins a **~1.5 GB heap**; it is
  opt-in precisely so a default up on a laptop never pays that cost or risks an OOM boot
  failure (§10.2). Nothing in the default path depends on ES being present.

### Boot ordering (§10.3)

- `migrate` `depends_on` `db: { condition: service_healthy }`; it runs `prisma migrate
  deploy` (+ the idempotent seed, `db`) and **exits 0** before `api`/`worker` start.
  Migrations are **never** in the `api` entrypoint — a one-shot service, so a crash-looping
  API can never race a half-applied schema.
- `api` and `worker` `depends_on` `{ db, redis, minio, migrate }` with
  `condition: service_healthy` (and `service_completed_successfully` for `migrate`).
- `edge` `depends_on` `web` + `api`. `web`/`api` readiness is their own healthcheck, not the
  edge's concern beyond ordering.

### Edge routes & headers (K14, §7.4, §8.1)

```
GET  /            → web:3000
     /api/*       → api:8080
     /assets/*    → minio:9000   (public-read bucket only)
     everything reached through the edge is same-origin — no CORS
```

- **CSP baseline:** `default-src 'self'`; `img-src 'self' data:`; `font-src 'self'` (fonts
  are self-hosted via `next/font`, §8.1 — no external font origin); `connect-src 'self'`
  **plus the voice provider's WSS/HTTPS origin** when the voice band lands (§7.4 — the exact
  origin is `voice`'s to supply; see Open questions). No `unsafe-inline` in `script-src`.
- **`/assets/*`** is stamped `Cache-Control: public, max-age=31536000, immutable` and reaches
  only the public-read bucket; private objects are **not** routable through `/assets` and are
  only reachable by signed URL (below).
- Standard hardening headers (`X-Content-Type-Options: nosniff`, `Referrer-Policy`,
  frame-ancestors) are set once at the edge.

### Object storage & access classes (K12)

| Class | Objects | Reach | Header |
|---|---|---|---|
| **public-read** | avatar WebP (`personas/{personaId}/{state}-{sha256}.webp`, `ui` §3.6) | `/assets/*` at the edge, no auth | `public, max-age=31536000, immutable` |
| **private** | uploaded CV/JD PDFs, generated report PDFs | **signed URL only**, short TTL | not public; no edge route |

- **Signed URLs** are S3 pre-signed GETs with a **short TTL (5 minutes, `SIGNED_URL_TTL`)**
  minted by `api`/`worker` using the MinIO credentials. The URL is the *only* way to read a
  private object; the bucket denies anonymous reads on the private prefix. Avatars are the
  **only** public objects (`ui` §3.6 asserts the classification; infra enforces it here).
- One bucket, prefix-scoped policy (public prefix `personas/`, everything else private), is
  the MVP shape — a second bucket is not required for two classes.

### Environment schema (§9.3)

- **One `env.ts` Zod schema**, validated **once at startup**; a missing or malformed var
  **fails fast** with a readable message naming the offending key(s) — the process exits
  non-zero and does not serve (`ENV_VALIDATION_FAILED`, below). No `process.env.X` read
  outside the validated, typed config object.
- **Config may be env-driven; behaviour may not** (§11.3). The same image runs in every
  environment; env supplies values (URLs, keys, budgets), never branches a business rule.
  There is no `if (NODE_ENV === 'production')` around behaviour anywhere.
- The committed **`.env.example`** enumerates every key with a safe placeholder and is the
  checklist a fresh clone fills in. Key groups (values owned by the cited area; infra owns
  only that they are declared, validated and delivered):

  | Group | Keys (illustrative) | Behaviour owner |
  |---|---|---|
  | Core | `DATABASE_URL`, `SHADOW_DATABASE_URL`, `REDIS_URL`, `PUBLIC_ORIGIN` | infra |
  | Storage | `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `SIGNED_URL_TTL` | infra |
  | LLM | `OPENAI_API_KEY`, `GEMINI_API_KEY`, model/price overrides | `ai` (§7.1, K15) |
  | Voice | `ELEVENLABS_API_KEY`, `ELEVENLABS_AGENT_ID_*` | `voice` (§3.5) — see Open questions |
  | Cost safety | `AI_ENABLED`, per-interview `MAX_SPEND_USD`, daily caps | `backend`/`ai` (§7.3) |
  | Auth | session/JWT secret | `auth`/`backend` |

  A key whose value is absent when its owning feature is enabled is that feature's fail-fast
  (e.g. `PROVIDER_KEY_MISSING`, owned by `ai`) — infra's env check is where the absence is
  caught, at boot, not at first request.

### Log transport (K6)

- Every service writes `logger.<level>({ …structured, traceId, interviewId }, "EVENT_NAME")`
  as **structured JSON to stdout** (pino). Infra owns that stdout is the transport and that
  Compose captures it; the **call-site contract (event name, `traceId`/`interviewId`, no
  secrets/PII) is honoured by each service**, not by infra.
- The **`observability` profile** ships stdout to Elasticsearch and exposes Kibana for
  search. With the profile off, logs remain on stdout / `docker compose logs` — full
  debuggability without ES. Turning the profile on adds a **sink**; it changes **no** log
  line and **no** behaviour.

### CI/CD (§11)

- **CI (PR):** install → **lint** (incl. commitlint / Conventional Commits) → **typecheck**
  → **build every image** → **migrate-check** (a throwaway Postgres + `prisma migrate diff`
  proves migrations are complete and the single `schema.prisma` has no drift, §5.2) →
  **Cucumber acceptance ring** against a Compose-booted default stack.
- **Migration collision guard (§5.2):** because `schema.prisma` is one file, two branches
  editing it collide at the migration level; CI's migrate-check fails a branch whose
  migrations don't cleanly apply onto `master`, forcing a rebase rather than a broken merge.
- **Deploy:** single VM, `docker compose` with the default profile (+ `observability` if the
  host affords it); image tags from the merge commit. No multi-node orchestration in scope
  (§11 — vertical first).

## Behaviour

Rules stated so two operators produce the same stack.

1. **A bare `docker compose up` boots a complete, seeded, single-origin app** — `edge web api
   worker db redis minio migrate`, no profile, no manual step. `migrate` applies the schema
   and seed before `api`/`worker` serve; the room works with avatars because seed uploaded
   them (`db`/`ui`). If a default up needs a hand-run command, that is a defect.
2. **Only `edge` publishes a port in `compose.yaml`.** Reaching `db`/`minio`/`api` directly
   requires the git-ignored `compose.override.yaml`; the stack's behaviour is identical with
   or without it (§10.2, §11.3).
3. **Migrations run as a one-shot service that exits 0 before the app serves** — never in an
   app entrypoint (§10.3). A failed migration stops the boot with a non-zero `migrate` exit;
   `api` never starts against a half-applied schema.
4. **Heavy/optional services are profile-gated.** `elasticsearch`/`kibana` (`observability`)
   and `tunnel` (`dev`) never start under a default up; the default path has no dependency on
   them, so their absence cannot fail a boot (§10.2).
5. **Env is validated once at startup and fails fast.** A missing/invalid key exits the
   process non-zero with the key named (`ENV_VALIDATION_FAILED`); nothing serves on bad
   config. No `process.env` read bypasses the typed config (§9.3).
6. **Config is env-driven; behaviour is not.** One image per service across all environments;
   env changes values, never branches a rule (§11.3). No behaviour keyed on `NODE_ENV`.
7. **Two storage access classes, enforced at the boundary.** Avatars (`personas/` prefix) are
   public-read and reachable at `/assets`; every other object is private and reachable only
   through a ≤5-minute signed URL. Anonymous read of a private object returns 403 from MinIO
   (K12).
8. **The edge is the single origin.** Browser traffic is same-origin through `edge`; no
   service is called cross-origin, so there is no CORS config and the CSP stays
   `default-src 'self'` save the one voice exception (§7.4).
9. **Logs are structured JSON on stdout; the ES sink is additive.** Enabling
   `observability` adds search, not information — every event already on stdout (K6).

## Failure modes

Infra failures are **boot- and ops-time**, not API envelopes. Codes are boot signals surfaced
in service logs / exit codes and (where app-level) added to the shared registry (`F01`).

| Condition | Code / signal | HTTP | Recovery |
|---|---|---|---|
| A required env var is missing/malformed at startup | `ENV_VALIDATION_FAILED` | — (process exits non-zero) | Fix `.env` against `.env.example`; the message names the key(s) (§9.3) |
| An enabled feature's provider key is absent | `PROVIDER_KEY_MISSING` (owned by `ai`, §7.1) | — (boot fail) | Supply the key; caught by the same env check, at boot not first request |
| A dependency is unhealthy at boot | Compose `service_healthy` wait / timeout | — | `edge`/`api`/`worker` do not start until deps pass their healthcheck; a dep that never becomes healthy fails the up (§10.3) |
| `prisma migrate deploy` fails | `migrate` exits non-zero | — | Boot stops before `api` serves; fix the migration and re-up — schema is never half-applied (§10.3, §5.2) |
| A branch's migrations don't apply onto `master` | CI migrate-check fails | — | Rebase; the single-file `schema.prisma` collision is caught in CI, never at merge (§5.2) |
| A private object is requested anonymously | MinIO `403` | 403 | Mint a signed URL; private objects are never public (K12) |
| A signed URL is used after its TTL | S3 `403` (expired) | 403 | Re-mint; TTL is `SIGNED_URL_TTL` (≤5 min) (K12) |
| The `observability` sink (ES) is down/absent | *(not an error)* | — | Logs stay on stdout; the profile is additive and never gates the app (K6, §10.2) |

## Observability

Infra is where observability *is provisioned*, so its own health is read from the platform:
each service's **healthcheck** is its liveness signal (`pg_isready`, `redis-cli ping`, MinIO
`/minio/health/ready`, `api` `/healthz`, `web` `GET /`), and `docker compose ps` /
`docker compose logs` is the first debugging surface with **no** profile enabled. The
**`observability` profile** adds Elasticsearch + Kibana so the structured stdout JSON (K6)
becomes searchable by `traceId`/`interviewId`/`EVENT_NAME` — the same fields already emitted,
now indexed. Infra's own boot events (migration applied, env validated, bucket policy
ensured) are logged through the same `logger` contract; **no secret, connection string, key
or PII is ever logged** — the env check names a *key's name*, never its value (§9.3, K6).

## Security

Infra owns the trust boundaries the whole system sits behind:

- **The edge is the only exposed surface.** Every other container is portless on a private
  Compose network; the attack surface is the single Caddy origin, hardened once with CSP
  (`default-src 'self'`), `nosniff`, `Referrer-Policy` and frame-ancestors (§7.4).
- **Secrets live only in env, never in the image or git.** `.env` is git-ignored; only
  `.env.example` with placeholders is committed. No key, credential or connection string is
  baked into a Dockerfile layer or logged (§9.3, K6). A build must not embed a secret.
- **Storage default-deny.** The bucket denies anonymous reads except the `personas/` public
  prefix; CV/JD/report objects are private and reached only by a short-TTL signed URL — a
  leaked URL expires in minutes (K12). Mis-classifying any private object as public is a
  data-exposure defect.
- **Same-origin, no CORS.** Because everything is reached through the edge, no cross-origin
  relaxation exists to be exploited (K14).
- **No environment-conditional behaviour** means no debug-only path, open port, or disabled
  check can slip into production through a branch — the same image runs everywhere (§11.3).
- **The `dev` tunnel is opt-in and non-default.** `cloudflared` exposes localhost only under
  the `dev` profile for provider webhooks (§3.5); it never runs in a default or prod up, so
  it opens no unintended ingress.

## Open questions

Each names who decides and what it blocks. Must be empty before `approved`.

1. **`tunnel` hostname → `PUBLIC_ORIGIN`/webhook wiring (§3.5).** IDEA.md says the tunnel's
   hostname "goes into `PUBLIC_ORIGIN`", but a `cloudflared` *quick* tunnel yields an
   **ephemeral** hostname per run, while a **named** tunnel needs a Cloudflare account/token.
   How the current hostname reaches `PUBLIC_ORIGIN` and any provider webhook registration is
   unsettled. **Decides:** `infra` + `voice` jointly, when the voice band lands. **Blocks:**
   local voice-webhook dev only — nothing in the MVP default path (no webhook until voice).
   **Recommended default:** named tunnel with a stable hostname wired statically into
   `.env`, falling back to a documented copy-the-quick-tunnel-URL step for contributors
   without a Cloudflare token.
2. **Voice provider keys & agent provisioning in `.env` (§3.5, §15.1.2).** Whether
   `ELEVENLABS_AGENT_ID_*` are created in the provider console (paste into `.env`) or created
   via API at startup/seed decides how many keys `.env.example` carries and whether a seeding
   step provisions agents. **Decides:** `voice` (owns the provider contract) + `infra` (owns
   `.env`/seed wiring). **Blocks:** the Voice env group's final key list and any provisioning
   step — deferred with the voice band; MVP `.env.example` carries them as commented
   placeholders.
3. **The voice provider's exact CSP `connect-src` origin (§7.4).** The edge CSP must widen
   `connect-src` to the ElevenLabs WSS/HTTPS origin for the voice room, but that origin is
   `voice`'s to supply. **Decides:** `voice`; `infra` parameterises the CSP to accept one
   extra origin. **Blocks:** the voice room's live connection only — the MVP text-mode CSP
   stays `default-src 'self'` with no exception.

## Acceptance criteria

Each observable from outside — a `docker compose up`, a healthcheck, a curl through the edge,
or a CI job result (verified in the acceptance ring where it touches the API, §5.3).

1. `docker compose up` with **no profile** brings `edge web api worker db redis migrate minio`
   to healthy and a browser reaching the edge origin gets a working, seeded app (avatars load)
   with **no** manual command (§10, §10.3).
2. **Only `edge` publishes a host port** in the committed `compose.yaml`; `docker compose port
   <svc>` returns nothing for every other service. Deleting a (git-ignored)
   `compose.override.yaml` changes no behaviour (§10.2, §11.3).
3. `migrate` **exits 0 before** `api`/`worker` start; forcing a migration error makes the up
   fail at `migrate` and `api` never serves against a partial schema (§10.3).
4. `elasticsearch`/`kibana` do **not** start without the `observability` profile, and `tunnel`
   does not start without `dev`; a default up succeeds with all three absent (§10.2).
5. Booting with a required env var removed exits the process **non-zero** with a message naming
   the missing key (`ENV_VALIDATION_FAILED`) and serves nothing (§9.3).
6. A `curl` to the edge for a `/assets/personas/...webp` returns the object with
   `Cache-Control: public, max-age=31536000, immutable`; an anonymous `curl` for a private
   object (PDF/report) returns **403**, and a signed URL for it returns 200 until its ≤5-minute
   TTL expires, then 403 (K12).
7. The edge response carries `Content-Security-Policy: default-src 'self'` (with the declared
   `font-src`/`img-src`), `X-Content-Type-Options: nosniff` and `Referrer-Policy`; no external
   font or asset origin is requested by the built app (§7.4, §8.1).
8. Every built image uses **repo root** as its build context and produces a runnable container
   that can resolve the shared workspace packages (§10.1).
9. Every service log line on stdout is structured JSON carrying `traceId`/`interviewId` where
   applicable and an `EVENT_NAME`; no line contains a secret, key, connection string or PII
   (K6, §9.3). With `observability` on, the same lines are searchable in Kibana.
10. CI on a PR runs lint (incl. commitlint) → typecheck → build all images → migrate-check →
    Cucumber acceptance ring, and **fails** a branch whose migrations don't apply onto
    `master` (§5.2, §11).
11. The same image runs across environments with only env differing; there is **no** code path
    branched on `NODE_ENV`/environment for business behaviour (§11.3).
12. `.env.example` is committed, lists every key the schema validates with safe placeholders,
    and a fresh clone that fills it in boots with no other configuration (§9.3).
